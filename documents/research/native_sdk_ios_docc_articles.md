
===== startusing | Начало работы с MapsNativeSDK
Интегрируйте карты в свое приложение на основе UIKit или SwiftUI.
## Шаг 1. Получите API-ключ для MapsNativeSDK
Подробнее о вариантах получения ключа читайте на api-key.
## Шаг 2. Подключите MapsNativeSDK к проекту
В данный момент MapsNativeSDK распространяется с помощью архива с несколькими `.xcframework`-пакетами.
-   Откройте свой проект с помощью Xcode.
-   Выберите необходимый target, в котором будут использоваться возможности SDK.
-   Во вкладке General добавьте все предоставленные `.xcframework`-файлы в раздел `Frameworks, Libraries, and Embedded Content`. На скриншоте ниже показан пример добавленных фреймворков в target.

## Шаг 3. Используйте MapsNativeSDK
### Импорт SDK
Импортируйте `MapsNativeSDK` в файл, в котором вы будете использовать карту.
```swift
import MapsNativeSDK
```
### Конфигурация SDK
Сконфигурируйте SDK, используя метод `MapsSDKConfigurator/setup(baseURL:apiKey:diskCachePath:maxCacheSizeBytes:fileTimeoutSec:)`.
```swift
// Конфигурация с передачей только API-ключа
MapsSDKConfigurator.setup(apiKey: ##API-ключ##)

// Конфигурация с передачей дополнительных параметров
MapsSDKConfigurator.setup(baseURL: ##Базовый URL для загрузки тайлов и предустановленных стиле##,
                          apiKey: ##API-ключ##,
                          diskCachePath: ##Путь для хранения файлов кэша на диске##,
                          maxCacheSizeBytes: ##Максимальный размер файлового кэша в байтах##,
                          fileTimeoutSec: ## Время жизни файлов в кэше ###)
```
> NOTE:
> Если не указать путь к файловому кэшу, то SDK не будет кешировать данные в виде файлов.
### Конфигурация карты
Создайте конфигурацию для карты с помощью типа MapConfiguration, указав исходные настройки карты.
```swift
// Кофигурация для карты с использованием предустановленного стиля
let configuration = MapConfiguration(
    center: ##Стартовые координаты центра карты##,
    zoom: ##Стартовый зум карты##,
    predefinedStyle: .simple
)
```
Вместо предустановленных стилей вы можете передать стиль, загруженный с помощью типа MapStyle или строку в формате JSON (подробнее в статье Styles).
### Создание делегата
Вам необходимо создать объект-делегат карты, в котором в дальнейшем вы сможете обрабатывать события жизненного цикла карты (подробнее в статье Lifecycle). При создании делегата подпишитесь на протокол MapViewDelegate.
```swift
// Определение класса-делегата
class BaseMapViewDelegate: MapViewDelegate {}

// ...

// Создание делегата
let delegate = BaseMapViewDelegate()
```
В дальнейшем данный объект потребуется передать при создании экземпляра типа MapView.
> NOTE:
> Не требуется реализовывать методы MapViewDelegate, если их функциональность вам не нужна.
### Размещение карт на экране
MapsNativeSDK могут быть использованы в приложениях, основанных на UIKit и SwiftUI. Далее рассмотрим каждую из платформ.
> NOTE:
> Убедитесь, что к этому моменту вы сконфигурировали SDK с помощью вызова `MapsSDKConfigurator.setup`.
#### Использование в UIKit-проекте
Для использования карты в UIKit необходимо создать объект MapView, передав в него конфигурацию, и разместить созданный объект на экране.
```swift
class ViewController: UIViewController {

    override func viewDidLoad() {
        super.viewDidLoad()
        // Конфигурирование SDK
        MapsSDKConfigurator.setup(apiKey: "...")
        // Создание конфигурации карты
        let configuration = MapConfiguration(center: Coordinates(lng: 37.6156, lat: 55.7522), zoom: 10, predefinedStyle: .main)
        // Создание объекта карты
        let mapView = MapView(frame: CGRect(x: 0, y: 0,
                                            width: UIScreen.main.bounds.width,
                                            height: UIScreen.main.bounds.height),
                              configuration: configuration,
                              delegate: self)
        // Размещение карты на экране
        view.addSubview(mapView)
    }
}

// Делегат карты
extension ViewController: MapViewDelegate {}
```
#### Использование в SwiftUI-проекте
Для использования карты в SwiftUI необходимо создать объект `MapView` и передать его в структуру `Map`.
```swift
// Делегат для MapView
class BaseMapViewDelegate: MapViewDelegate {}

// View-модель экрана, где будет использоваться карта
final class ContentViewModel: ObservableObject {
    // Объект карты
    let mapView: MapView
    // Объект делегата карты
    private let mapViewDelegate: MapViewDelegate
    
    init() {
        // Конфигурирование SDK
        MapsSDKConfigurator.setup(apiKey: "...")
        // Создание конфигурации карты
        let configuration = MapConfiguration(center: Coordinates(lng: 37.6156, lat: 55.7522), zoom: 10, predefinedStyle: .main)
        // Создание делегата карты
        let delegate = BaseMapViewDelegate()
        mapViewDelegate = delegate
        // Создание объекта карты
        mapView = MapView(configuration: configuration, delegate: delegate)
    }
}

// Экран с картой
struct ContentView: View {
    @StateObject private var viewModel = ContentViewModel()

    var body: some View {
        Map(view: viewModel.mapView)
            .frame(maxWidth: .infinity, maxHeight: .infinity)
    }
}
```

===== lifecycle | Отслеживание событий карты
Отслеживайте события, происходящие с картой, и программируйте реакцию на них.
## Обзор
В процессе работы карта изменяет состояние, как вследствии запрограммированной в SDK логики (загрузка карты и стилей, смена режимов следования), действий пользователя (жесты, взаимодействие с маркерами), так и вследствии вызовов методов `flyTo`, `setBearing` и других. Используя делегат карты вы можете реагировать на изменение состояния, отслеживая следующие события:
-   карты отображена на экране;
-   стиль загружен;
-   камера перемещена;
-   нажатие на маркер;
-   нажатие на карте;
-   долгое нажатие на карту;
-   смена режима следования;
-   различные ошибки.
> NOTE:
> Процесс создания делегата карты описан в статье StartUsing
### Методы делегата
MapViewDelegate предоставляет возможность реализации следующих методов:
-   mapView(_:didReceiveEvent:) для отслеживания событий.
-   mapView(_:willChangeModeTo:)-kz0b для определения режима следования, который будет включен.
-   mapView(_:didChangeModeTo:)-605ey для определения режима следования, который был включен.
-   mapView(_:didFailWithError:) для определения ошибки.
#### Отслеживание событий
В метод `mapView(_:didReceiveEvent:)` передается значение типа MapEvent, описывающее произошедшее событие. Далее рассмотрим каждый из возможных вариантов событий.
> NOTE:
> Метод `mapView(_:didReceiveEvent:)` может быть вызыван с произвольного потока. Если вам требуется обновить UI, то вы должны самостоятельно произвести переключение на главный поток.
##### Карта была отображена на экране (.mapDidShow)
Данное событие передается сразу после отображения карты на экране устройства.
##### Стиль был загружен (.styleDidLoad)
Данное событие передается сразу после загрузки стиля. Работа со стилями производится с помощью типа MapStyle. Подробнее в статье Styles.
##### Событие перемещения камеры (.cameraDidMove)
При любом перемещении камеры в метод `mapView(_:didReceiveEvent:)` передается значение cameraDidMove(state:reason:phase:), которое описывает характеристики перемещения камеры.
Объект `cameraDidMove` имеет следующие ассоциированные значения:
-   `state: CameraPosition` - описывает текущее положение камеры.  Подробнее - CameraPosition.
-   `reason: CameraMovingReason` - описывает причину перемещения камеры.  Подробнее - CameraMovingReason.
-   `phase: CameraMovingPhase` - описывает текущую фазу перемещения камеры (перемещение началось, продолжается или закончилось). Подробнее - CameraMovingPhase.
Ниже показан пример использования метода `mapView(_:didReceiveEvent:)` для анализа перемещения камеры.
```swift
func mapView(_: MapView, didReceiveEvent event: MapEvent) {
    switch event {
    case let .cameraDidMove(state, reason, phase):
        print("Событие перемещения камеры")
        print("Текущее положение камеры - \(state)")
        print("Причина перемещения камеры - \(reason)")
        print("Фаза перемещения камеры - \(phase)")
        print("---")
    default: break
    }
}
```

===== styles | Оформление карты
Изменяйте внешний вид карты, рисуйте геометрические фигуры и размещайте маркеры.
## Overview
При работе с картой в MapsNativeSDK вы можете гибко управлять ее внешим видом: изменять видимость объектов, их оформление, наносить геометрические фигуры и маркеры. В этой статье мы подробно рассмотрим доступные возможности оформления карты.
### Стиль
Стиль - это информация в формате JSON, которая определяет, что и в каком порядке должно быть нарисовано на карте, и как оно должно быть оформлено. Спецификация стиля довольно обширна и позволяет отображать на карте большое количество разнообразных объектов. В общем случае стиль состоит из источников данных (описывают, что должно быть отображено) и слоев (описывают, как это отображать).
В MapsNativeSDK для работы со стилями предназначен тип MapStyle.
### Источник данных
Источник данных - это информация в формате JSON, описывающая формат данных для отображения на карте, и способ их получения (может как содержать данные напрямую, так и ссылку на эти данные). Источники данных входят в состав стиля, в процессе работы с картой их можно удалять и добавлять новые.
В настоящий момент MapsNativeSDK поддерживает два типа источников данных: векторные данные и GeoJSON. Примеры векторных источников данных: тайлы, информация о пробках, изолинии. Примеры данных в формате GeoJSON: полигоны.
В MapsNativeSDK для работы с источниками данных предназначен тип MapDataSource.
Более подробно о формате источников данных можно прочитать в .
### Слой
Слой - это информация в формате JSON, которая определяет внешний вид данных, описанных в Источниках данных. Другими словами, слой определяет как данные должны быть отображены (и отображены ли вообще). К примеру, у вас может быть источник данных о пробках на дорогах и стиль, определяющий как именно раскрашивать дороги в зависимости от балла пробок.
В MapsNativeSDK для работы с источниками данных предназначен тип MapLayer.
Более подробно о формате слоев можно прочитать в .
## Основы работы со стилями
### Создание стиля
Для создания стиля используется один из доступных инициализаторов типа `MapStyle`.
```swift
// Создание пустого стиля
let emptyStyle = MapStyle()

Task {
    // Загрузка предустановленного стиля
    let simplePredefinedStyle = try await MapStyle(predefinedStyle: .simple)

    // Загрузка стиля по определенному URL
    let styleFromURL = try await MapStyle(url: styleURL)
    
    // Загрузка стиля из строки в формате JSON
    let styleFromJSON = try await MapStyle(json: styleJSON)
}
```
> NOTE:
>  Обратите внимание, что в большинстве случаев инициализаторы типа `MapStyle` является асинхронными.
#### Предустановленные стили
Предустановленные стили - это стили, которые предоставляет VK для использования . Вам доступны следующие предустановленные стили:
-   simple - упрощенный стиль без акцентов.
-   main - основной стиль с акцентами на POI и дорогах.
-   dark - темный стиль с акцентами на POI и дорогах.
-   navigationMain - навигационный стиль с акцентами на дорогах.
-   navigationDark - темный навигационный стиль с акцентами на дорогах.
> NOTE:
>  Предустановленные стили не входят в комплект поставки MapsNativeSDK и загружаются по сети.
> NOTE:
>  Для загрузки предустановленных стилей используется базовый URL, указываемый при конфигурировании SDK с помощью `MapsSDKConfigurator/setup(baseURL:apiKey:diskCachePath:maxCacheSizeBytes:fileTimeoutSec:)`.
### Использование стилей при создании MapView
При создании объекта `MapView` необходимо передать конфигурацию типа MapConfiguration, в которой указывается, какой стиль будет использоваться для карты.
> NOTE:
>  Пока стиль не будет применен к карте на ней будет отображаться заполнитель в виде сетки.
> NOTE:
>  При использовании в `MapConfiguration` предустановленного стиля, URL для загрузки стиля или стиля в формате JSON, стиль будет применен к карте (и соответственно карта отобразится) только после его загрузки и обработки. Это может привести к тому, что некоторое время вместо карты вы будете видеть заполнитель.
Подробнее о создании объекта `MapView` читайте в статье StartUsing.
### Получение текущего стиля карты
Для получения текущего стиля карты предназначено свойство style. В том случае, если стиль еще не был загружен и применен, данное свойство вернет `nil`.
```swift
// текущий стиль карты
let currentStyle = mapView.style
```
> NOTE:
>  Тип `MapStyle` - это структура (реализует семантику значений). Это значит, что свойство `style` возвращает копию текущего стиля, и все изменения, проведенные с ним, не применятся к карте, пока модифицированный стиль не будет установлен с помощью метода `setStyle(_:)`.
### Применение стиля к карте
Для применения стиля к карте используется метод `MapView/setStyle(_:)`, который принимает значение типа `MapStyle`.
```swift
// загрузка предусткновленного стиля
let currentStyle = mapView.style
```
### Изменение текущего стиля карты
Для изменения текущего стиля карты вам необходимо:
-   Получить копию текущего стиля с помощью свойства style.
-   Модифицировать стиль (например добавить/удалить источники данных и слои).
-   Применить измененный стиль к карте.
Далее приведен пример скрытия определенного слоя.
```swift
// загружаем стиль
if let style = mapView.style, let layer =  {
    // скрываем слой
    style.layer(by: "water")?.isVisible = false
    // применяем измененный стиль к карте
    mapView.setStyle(style)
}
```
> NOTE:
>  Тип `MapLayer` - это класс (реализует ссылочную семантику). Это значит, что вы можете работать со слоем напрямую через доступные свойства и метода объекта-стиля.
### Пустой стиль в качестве первоначального для карты
В качестве первоначального стиля вы можете передать пустой стиль. Это может потребоваться в том случае, когда вам необходимо провести дополнительную работу над стилем, который вы хотите применить к карте.
```swift
// Синхронное создание объекта mapView
// в качестве стиля передается пустой стиль
let style = MapStyle()
let configuration = MapConfiguration(center: Coordinates(lng: 35.910974, lat: 56.859207), zoom: 15, style: style)
mapView = MapView(configuration: configuration)

// Запуск асинхронной задачи на модификацию стиля с его последующей установкой в mapView
Task {
    // загрузка предустановленного стиля
    let style = try await MapStyle(predefinedStyle: .main)
    
    // ...
    // выполнение сложной работы по модификации стиля
    // например скрытие слоев, добавление источников данных
    // ...
    
    // установка стиля в карту
    await mapView.setStyle(style)
}
```
Идея данного примера в том, что вы синхронно создаете объект карты, а всю работу по конфигурированию стиля выволняете асинхронно.
## Нанесение элементов на карту
В данный момент MapsNativeSDK поддерживает три способа нанесения элементов на карту:
-   Добавление источников данных и слоев.
-   Добавление маркеров `PlatformMarker`.
-   Добавление маркеров Marker.
Далее более подробно рассмотрим каждый из них.
### Работа с источниками данных и слоями
С помощью источников данных и слоев вы можете наносить на карту полигоны и полилинии, создавая таким образом произвольные геометрические фигуры. В приведенном примере показана карта с нанесенным на нее полигоном.
> NOTE:
>  В MapsNativeSDK постепенно добавляются новые удобные способы нанесения обстановки на карту с использованием всех возможностей Swift.
> Тем не менее в настоящий момент основным инструментом является непосредственная работа с форматом GeoJSON. Таким образом потребуется самостоятельно формировать данные, описывающие полигоны и полилинии, после чего добавлять их в стиль. Для вашего удобства разработан сервис geojson.io, с помощью которого вы сможете визуально создавать и редактировать объекты, после чего переносить их в MapsNativeSDK.
> Так же настоятельно рекомендуем ознакомиться со geojson.org и описание данного формата на сайте .
Источники данных и слои - это составная часть стиля, и когда вы редактируете источники данных или слои, то по сути редактируете стиль. Именно поэтому доступ к соответсвующим методам (addSource(_:), addLayer(_:) и др.) происходит через экземпляр типа MapStyle.

Источник данных описывает, что будет отображено на карте, а слой - как это будет выглядеть. Для того, чтобы нанести полигон (точку, полилинию или другой поддерживаемый объект), необходимо добавить и источник данных, и слой. Далее приведен пример добавления полигона на карту.

===== cameramoving | Управление камерой
Изменяйте положение камеры в пространстве, управляя ее координатами, уровнем увеличения, наклоном, поворотом и другими параметрами.
## Overview
MapsNativeSDK предоставляет широкие возможности для управления камерой в процессе использования приложения. С помощью камеры вы определяете, какую информацию показать пользователю на карте. Камера перемещается над поверхностью карты для отображения необходимых объектов. Это может происходить в следствии использования пользователем жестов, нажатия кнопок управления камерой, вызова методов управления камерой, работы режима следования и по другим причинам.
### Отступы (paddings)
### Ограничительная рамка (bounding box)
Ограничительная рамка - это прямоугольник с географическими координатами севево-восточного и юго-западного углов, характеризующего положение камеры в пространстве.
Далее показан пример определения ограничительно рамки в двух случаях, когда поворот камера равен нулю и когда камера повернута на 45 градусов. В первом случае рамка соответствует области, которую отображаем камера, во втором область камеры вписывается в ограничительную рамку.
Ограничительная рамка используется, когда вам необходимо вписать объект (например полигон или множество маркеров) в камеру, для этого используется метод `CameraController/fitBounds(_:padding:animationDuration:reason:)`.
Также доступен метод calculateBoundingBox(coordinates:cameraOptions:), позволяющий рассчитать, какие будут географические координаты у северо-восточного (правый-верхний) и юго-западного (левый нижний) углов вьюпорта, не перемещая фактически камеру в заданную область.
> NOTE:
>  Ограничительная рамка учитывает установленные отступы для камеры.
## Характеристики положения камеры
При описании позиции камеры в пространстве используются следующие характеристики:
-   Координаты центра с учетом отступов.
-   Уровень увеличения (zoom).
-   Угол наклона (pitch).
-   Угол поворота (bearing).
-   Координаты вписанного в камеру прямоугольника (bounding box).
-   Причина перемещения камеры в новую позицию (только при использовании делегата).
-   Фаза пемещения камеры (только при использовании делегата).
-   Количество точек на метр (только при использовании контроллера камеры).
-   Количество метров в одной точке (только при использовании контроллера камеры).
Для определения характеристик текущей позиции камеры вы можете использовать делегат карты или обращаться к контроллеру камеры.
### Использование делегата карты
Каждое изменение положения камеры приводит к вызову метода mapView(_:didReceiveEvent:)-7k969 с передачей в него значения cameraDidMove(state:reason:phase:), с помощью которого вы можете определить текущие характеристики положения камеры, причину движения и его текущую фазу.
#### Характеристики положения камеры (параметр state)
Параметр `state` содержит значение типа CameraPosition, с помощью которого можно получить характеристики текущего положения камеры:
-   Координаты центра с учетом отступов (свойство center).
-   Уровень увеличения (свойство zoom).
-   Угол наклона (свойство pitch).
-   Угол поворота (свойство bearing).
-   Координаты вписанного в камеру прямоугольника (свойство bounds).
#### Причина перемещения камеры (параметр reason)
Параметр `reason` содержит значение типа CameraMovingReason, с помощью которого можно определить, по какой причине было произведено перемещение камеры. К примеру, если камера перемещается вследствии жеста, то `reason` будет иметь значение `MapEvent/CameraMovingReason/gesture`. MapsNativeSDK позволяет с большой точностью определять причину перемещения камеры. Для уточнения всех возможных причин перейдите к документации типа CameraMovingReason.
При использовании описанных далее методов у вас есть возможность в качестве причины передать произвольный объект, получив его обратно в методе mapView(_:didReceiveEvent:)-7k969 делегата карты.
```swift
// Произвольный тип, используемый для описания причины перемещения
// Подобный тип вы определяете самостоятельно
enum CustomReason {
    case customButton
    case customGesture
}

// Вызов метода перемещения камеры
// В качестве причины передаем значение определенного выше типа 
// Но в данном случае вы не ограничены ничем, можете передавать любые значения любых типов
mapView.camera.setBearing(degrees: 30, reason: CustomReason.customButton)

// ...

func mapView(_: MapView, didReceiveEvent event: MapEvent) {
    if case let .cameraDidMove(state: state, reason: reason, phase: phase) = event {
        // Кастомное значение будет содержаться внутри значения MapEvent.CameraMovingReason.custom
        switch reason {
        case let .custom(reason: customReason):
            guard let reasonFromEvent = customReason as? CustomReason else { return }
            // Получим именно то значение, которое было передано
            reasonFromEvent == .customButton // true
        default: 
            return
        }
    }
}
```
> NOTE:
>  В качестве причины вы можете передавать объекты с семантикой ссылок или значений, на свой выбор. MapsNativeSDK самостоятельно следит за временем жизни переданного объекта.
При этом аргумент `reason` не является обязательным, по умолчанию MapsNativeSDK присылает значение code в качестве причины перемещения.
#### Фаза перемещения камеры (параметр phase)
Параметр `phase` содержит значение типа CameraMovingPhase, с помощью которого вы можете получить информацию о фазе перемещение камеры. Фаза позволяет определить:
-   началось ли движение камеры;
-   продолжается ли движение камеры;
-   закончилось ли движение камеры.
К примеру, если пользователь перемещает камеру с помощью жеста, то в первый кадр перемещения параметр `phase` будет иметь значение began, далее - changed, а в последний кадр (сразу после того, как пользователь прекратит жест, то есть завершит касание экрана) - singleCompleted. После этого будет запущена анимация инерции (параметр `reason` будет содержать значение inertia), фазы которой меняются в том же порядке. После завершения инерции считается, что жест полностью завершен и поступает значение allCompleted.
Аналогичная логика работает и для вызова методов перемещения камеры, которые будут рассмотрены далее. Так если вы запускаете анимированное перемещение камеры, то в первый кадр перемещения параметр `phase` будет иметь значение began, далее - changed, а в последний кадр - singleCompleted, после чего поступает значение allCompleted. При этом, если анимация перемещения была отменена (о способах отмены будет рассказано далее), то вы получите значение cancelled.
Обратите внимание, что зачастую singleCompleted и allCompleted поступают последовательно одно за другим, сообщая о том, что “текущая анимация камеры завершена” и “анимация камеры завершена полностью”. Но в отдельных случаях вы можете получить несколько значений singleCompleted в процессе движения камеры, в частности, когда используете комбинированные анимации (о них будет рассказано далее).
В случае, когда камера перемещается без анимации, в качестве фазы поступает значение singleCompleted.
Таким образом вы можете реализовывать сложную логику, основанную на причине и фазе перемещения. К примеру скрывать отдельные элементы UI в процессе применения пользователем жестов.
#### Сводный список событий при перемещении камеры
Существует множество способов перемещния камеры, каждый из которых будет подробно рассмотрен далее. Для каждого из этих способов перечень событий cameraDidMove(state:reason:phase:) может отличаться. Далее приведен перечень событий для каждого из методов.
```
// Жест с запуском инерции
// - прокрутка с отпускание пальца в движении по экрану
// - поворот с отпускание пальцев в движении по экрану
// - щепок с отпускание пальцев в движении по экрану
.cameraDidMove(state: _, reason: .gesture, phase: .began)
.cameraDidMove(state: _, reason: .gesture, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .gesture, phase: .ended)
.cameraDidMove(state: _, reason: .inertia, phase: .began)
.cameraDidMove(state: _, reason: .inertia, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .inertia, phase: .ended)
.cameraDidMove(state: _, reason: .gesture, phase: .finished)

// Жест без запуска инерции
// - прокрутка с отпускание пальца после его остановки
// - поворот с отпускание пальцев после его остановки
// - щепок с отпускание пальцев после его остановки
// - двойной тап для изменения масштаба
// - касание двумя пальцами для изменения масштаба
// - двойное касание с прокруткой для изменения масштаба
// - наклон
.cameraDidMove(state: _, reason: .gesture, phase: .began)
.cameraDidMove(state: _, reason: .gesture, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .gesture, phase: .ended)
.cameraDidMove(state: _, reason: .gesture, phase: .finished)

// Нажатие на Компас
.cameraDidMove(state: _, reason: .control(.compass), phase: .began)
.cameraDidMove(state: _, reason: .control(.compass), phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .control(.compass), phase: .ended)
.cameraDidMove(state: _, reason: .control(.compass), phase: .finished)

// Нажатие на кнопку текущей локации
.cameraDidMove(state: _, reason: .control(.currentLocation), phase: .began)
.cameraDidMove(state: _, reason: .control(.currentLocation), phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .control(.currentLocation), phase: .ended)
.cameraDidMove(state: _, reason: .control(.currentLocation), phase: .finished)

// Изменение вследствие работы режима следования
.cameraDidMove(state: _, reason: .followMode, phase: .began)
.cameraDidMove(state: _, reason: .followMode, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .followMode, phase: .ended)
.cameraDidMove(state: _, reason: .followMode, phase: .finished) // после отмены текущего режима следования 

// Нажатие на кнопки изменения масштаба
.cameraDidMove(state: _, reason: .control(.zoomButtons), phase: .began)
.cameraDidMove(state: _, reason: .control(.zoomButtons), phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .control(.zoomButtons), phase: .ended)
.cameraDidMove(state: _, reason: .control(.zoomButtons), phase: .finished)

// Изменение масштаба через прозрачную область в правой части экрана
.cameraDidMove(state: _, reason: .control(.zoomArea), phase: .began) // в момент касания области
.cameraDidMove(state: _, reason: .control(.zoomArea), phase: .changed) // в процессе движения пальцем
.cameraDidMove(state: _, reason: .control(.zoomArea), phase: .ended) // после отрыва пальца от экрана
.cameraDidMove(state: _, reason: .control(.zoomArea), phase: .finished)

// Изменение вследствие вызова методов flyTo и других методов изменения положения камеры
// В качестве причины по умолчанию передается .code, но вы можеет передать собственный объект
.cameraDidMove(state: _, reason: .code, phase: .began)
.cameraDidMove(state: _, reason: .code, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .code, phase: .ended)
.cameraDidMove(state: _, reason: .code, phase: .finished)

// Изменение вследствие вызова метода flyTo в процессе работы другого flyTo
.cameraDidMove(state: _, reason: .code, phase: .began)
.cameraDidMove(state: _, reason: .code, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .code, phase: .cancelled) // предыдущий flyTo отменяется
.cameraDidMove(state: _, reason: .code, phase: .began) // начинается новый flyTo
.cameraDidMove(state: _, reason: .code, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .code, phase: .ended)
.cameraDidMove(state: _, reason: .code, phase: .finished)

// Изменение вследствие вызова метода изменения положения камеры (не flyTo, например setBearing с анимацией) в процессе работы flyTo
.cameraDidMove(state: _, reason: .code, phase: .began) / начинается анимация flyTo
.cameraDidMove(state: _, reason: .code, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .code, phase: .began) // начинается анимация по вызову нового метода
.cameraDidMove(state: _, reason: .code, phase: .changed) // изменение камеры по двум методам сразу, может повторяться множество раз
.cameraDidMove(state: _, reason: .code, phase: .ended) // заканчивается первая анимация (та, которая кончится раньше)
.cameraDidMove(state: _, reason: .code, phase: .changed) // может повторяться множество раз
.cameraDidMove(state: _, reason: .code, phase: .ended) // заканчивается вторая анимация
.cameraDidMove(state: _, reason: .code, phase: .finished)

```
### Использование контроллера камеры
Актуальные характеристики камеры всегда можно получить, обращаясь к контроллеру камеры через свойство camera.
```swift
// Координаты центра карты с учетом отступов
mapView.camera.centerCoordinates
// Уровень увеличения
mapView.camera.zoom
// Угол поворота в градусах
mapView.camera.bearing
// Координаты прямоугольника, вписываемого в камеру
mapView.camera.mapBounds

// Количество метров в точке при текущем зуме
mapView.camera.metersPerPoint(zoom: mapView.camera.zoom,

// Количество метров в точке при зуме 15 в координатах центра камеры
mapView.camera.pointsPerMeter(zoom: 15,

```
## Изменение положения камеры
Для изменения положения камеры используются следующие способы:
-   Жесты.
-   Элементы управления (кнопки).
-   Режимы следования.
-   Методы API.
### Жесты
Для управленяи положением камеры можно использовать большое количество встроенных в SDK жестов. Всего пользователю доступны следующие жесты:
-   Прокрутка (Перемещение камеры по осям X и Y).
-   Наклон
-   Щепок (pitch).
-   Двойное касание.
-   Касание двумя пальцами.
-   Двойное касание с прокруткой.
-   Поворот.
Более подробно об использовании и управлении жестами читайте в статье Gestures.
### Элементы управления
Для управления положением камеры можно использовать следующие элементы управления:
-   Компас - при нажатии на компас угол поворота камеры анимировано выставляется на ноль (север сверху).
-   Область изменения зума - при касании данной области пальцем и скролле вверх/вниз будет изменяться уровень увеличения.
-   Кнопки изменения зума.
-   Кнопка текущей позиции - при нажатии на кнопку меняется режим следования камеры.
Более подробно об использовании и управлении элементами управления читайте в статье Controls.
### Режимы следования
Для управления положение камеры можно использовать режимы следования. Режим следования описывает способ привязки камеры к индикатору пользователя. Вам доступны следующие режимы:
-   Свободный - камера не закреплена на индикаторе пользователя и может свободно перемещаться.
-   Следование локации - центр камеры (с учетом установленных отступов) зафиксирован на индикаторе пользователя и перемещается вслед за ним.
-   Следование локации и направления - центр камеры (с учетом установленных отступов) зафиксирован на индикаторе пользователя и перемещается вслед за ним. Так же поворот камеры соответствует направлению лучу на индикаторе пользователя.
Подробнее о режимах следования читайте в статье FollowingMode.
### Методы API
MapsNativeSDK имеет большое количество методов, позволяющих гибко управлять положением камеры относительно карты.
#### flyTo
Метод `CameraController/flyTo(coordinates:cameraOptions:animationOptions:reason:)` позволяет переместить камеру в новую позицию.
```swift
// координаты центра камеры
let centerCoordinates = Coordinates(lng: 35.910974, lat: 56.859207)
// дополнительные параметры камеры
let cameraOptions = MapCameraOptions(bearing: 90, zoom: 15, pitch: nil, padding: nil)
// настройки анимации
let animationOptions = MapAnimationOptions(easing: .linear, duration: .linear(value: 3))
// перемещение камеры в новую позицию
let movingResult = await mapView.camera.flyTo(coordinates: .center(centerCoordinates),
                           cameraOptions: cameraOptions,
                           animationOptions: animationOptions,
                           reason: nil)
```
Метод `flyTo` возвращает информацию о том, по какой причине завершилась анимация:
-   ended - завершилась по достижению намеченной точки.
-   cancelled - была отменена вследствии повторного вызова `flyTo`, вызова stopAnimation(), пользовательских жестов или по другим причинам.
> NOTE:
>  Вызов flyTo отменяет текущую анимацию камеры.
> NOTE:
>  В SDK есть “классическая” версия с коллбеком `CameraController/flyTo(coordinates:cameraOptions:animationOptions:reason:completion:)`.
#### Дополнительные методы управления камерой
Несмотря на то, что `flyTo` позволяет решить практически любую задачу позиционирования камеры, в MapsNativeSDK есть дополнительные методы.
-   setBearing(degrees:animationDuration:reason:) - изменение угла поворота камеры.
-   setZoom(_:anchor:animationDuration:reason:) - изменение уровня зума.
-   zoomIn(step:animationDuration:reason:) - увеличение значения зума.
-   zoomOut(step:animationDuration:reason:) - уменьшение значения зума.
-   setZoomRange(minZoom:maxZoom:) - изменение доступного диапазона значений зума.
-   setPitch(degrees:animationDuration:reason:) - изменение угла наклона камеры.
-   setBearing(degrees:animationDuration:reason:) - изменение угла поворота камеры.
-   setPadding(_:animationDuration:reason:) - изменение отступов.
-   `CameraController/fitBounds(_:padding:animationDuration:reason:)` - вписывание области в камеру.
#### Анимация перемещения камеры
Практически каждый из вызовов описанных выше методов может анимироваться с помощью передачи параметров: `animationOptions` для `flyTo` и `animationDuration` для всех остальных.
В то время, как для большинства методов требуется передать значение типа `TimeInterval`, определяющее количество секунд анимации перемещения, вызов `flyTo` позволяет более гибко настроить этот процесс. В частности для описания параметров анимации используется тип MapAnimationOptions, который позволяет определить кривую плавности анимации и ее длительность. Ниже приведены несколько примеров создания объектов данного типа стг пояснениями.
```swift
// линейная анимация длительностью 10 секунд
let animationOptions = MapAnimationOptions(easing: .linear, duration: .linear(value: 10))

// анимация с кривой ускорения типа easyIn длительностью 3 секунды
let animationOptions = MapAnimationOptions(easing: .easyIn, duration: .linear(value: 3))

// линейная анимация длительностью НЕ БОЛЕЕ 5 секунд
let animationOptions = MapAnimationOptions(easing: .linear, duration: .max(value: 5))
```
Значение `MapAnimationOptions/Duration/max(value:)` позволяет указать предельную допустимую длительность анимации. Другими словами, анимация может длиться 5 или менее секунд, но не больше этого предела. К примеру если вы передвигаете камеру на малое расстояние по карте, то при подобном использовании анимация с большой долей вероятности будет идти менее 5 секнуд. Но если вы перемещаете камеру на большие расстояния (например между континентами), то длительность пермещения будет гарантировано не более 5 секунд.
##### Отмена текущей анимации
Для отмены текущей анимации перемещения камеры вы можете использовать повторный вызов `flyTo` (в этом случае будет запущено новое перемещение камеры), или метод stopAnimation().
При досрочном прерывании анимации событие cameraDidMove(state:reason:phase:) в параметре `phase` будет содержаться значение cancelled.
##### Комбинированные анимации
Стоит помнить, что повторный вызов `flyTo` отменяет текущую анимацию камеры, но при этом вызовы остальных методов перемещения камеры этого не делают,а значит при необходимости вы можете создавать комбинированные анимации с разной длительностью. Рассмотрим пример:
```swift
// изменение угла поворота
mapView.camera.setBearing(degrees: 90, animationDuration: 3)
// изменение центральной точки
await mapView.camera.flyTo(coordinates: .center(Coordinates(lng: 35.910974, lat: 56.859207)),
                           animationOptions: MapAnimationOptions(easing: .linear,
                                                                 duration: .linear(value: 6)))
```
В данном примере мы запускаем две анимации: изменение угла поворота длительностью 3 секунды и изменение координат центральной точки длительностью 6 секунд. При этом движение камеры будет единым. В итоге, после того, как камера завершит анимированный поворот, она еще 3 секунды будет двигаться к новой центральной точке. При этом после завершения первой анимации в делегате карты параметр `phase` будет содержать значение singleCompleted, а после завершения второй анимации будут получены два события: первое с фазой singleCompleted, второй с фазой allCompleted, сообщающее о полном завершении анимации.

===== followingmode | Режимы следования
Используйте режимы следования для определения логики привязки камеры к индикатору пользователя.
## Overview
Режим следования описывает способ привязки камеры к индикатору пользователя. Вам доступны следующие режимы:
-   Свободный - камера не закреплена на индикаторе пользователя и может свободно перемещаться.
-   Следование локации - центр камеры (с учетом установленных отступов) зафиксирован на индикаторе пользователя и перемещается вслед за ним.
-   Следование локации и направления - центр камеры (с учетом установленных отступов) зафиксирован на индикаторе пользователя и перемещается вслед за ним. Так же поворот камеры соответствует направлению лучу на индикаторе пользователя.
Режим следования может изменяться с помощью нажатия кнопки “Текущая позиция” или вызова специальных методов. При смене режима следования кнопка “Текущая позиция” изменяет внешний вид.
В приведенном примере показаны три доступных в SDK режима следования.
В общем случае режимы следования могут изменяться по следующим причинам:
-   Нажатие кнопки “Текущая позиция” - происходит переключение на следующий режим следования.
-   Вызов метода onTapCurrentLocationButton() - аналогичен нажатию на кнопку “Текущая позиция”.
-   Вызов метода setMode(_:) - принудительная установка режима следования.
-   Использование некоторых жестов на карте - принудительно включает свободный режим.
## Управление режимами следования
Режим следования описывается с помощью перечисления MapMode.
```swift
// свободный режим
MapMode.free
// режим следования локации
MapMode.followLocation
// Режим следования локации и направления
MapMode.followBearingAndLocation
```
Для определения текущего режима следования используйте свойство mode.
```swift
mapView.mode
```
Для изменения текущего режима следования используйте метода setMode(_:).
```swift
// принудительная установка свободного режима 
mapView.setMode(.free)
```
## Контроль режимов следования
При смене режима следования (в процессе нажатия соответствующей кнопки в UI или по другим причинам) последовательно вызываются два метода делегата:
-   mapView(_:willChangeModeTo:)-kz0b с указанием, какой режим следования предполагается включить.
-   mapView(_:didChangeModeTo:)-605ey с указанием, какой режим следования был включен.
Метод `mapView(_:willChangeModeTo:)` принимает значение типа MapMode, которое определяет режим следования предполагается включить. Так же он требует вернуть режим, который будет включен. Таким образом вы можете контролировать доступные в приложении режимы, как показано в следующем примере.
```swift
func mapView(_: MapView, willChangeModeTo nextMode: MapMode) -> MapMode {
    // Если предпологается включить режим следования локации и направления
    // то вместо него включаем свободный режим
    // Таким образом режим следования локации и направления будет недоступен
    // и вместо него всегда будет включаться свободный режим
    if nextMode == .followBearingAndLocation {
        MapMode.free
    } else {
        nextMode
    }
}
```

===== gestures | Жесты
Управляйте картой с помощью широкого списка доступных жестов.
## Overview
MapsNativeSDK предоставляет максимально привычные для пользователя iOS жесты для перемещения камеры в пространстве. Далее подробно рассмотрим каждый из них.
## Прокрутка (Перемещение камеры по осям X и Y).
Проведите одни или двумя пальцами в произвольном направлении, чтобы изменить координаты центра камеры.
Для отключения жеста используйте свойство isScrollGesturesEnabled.
```swift
mapView.isScrollGesturesEnabled = false
```
Прокрутка двумя пальцами может производить в рамках единого жеста с масштабирование и поворотом.
> NOTE:
>  Если жест начинается с перемещения двух пальцев в вертикальном направлении, то активируется изменение наклона, вместо перемещения камеры по осям X и Y.
## Наклон
Проведите двумя пальцами в вертикальном направлении, чтобы наклонить камеру относительно горизонтальной плоскости карты.
Для отключения жеста используйте свойство `MapView/isPitchGesturesEnabled`.
```swift
mapView.isPitchGesturesEnabled = false
```
## Масштабирование (Перемещение камеры по оси Z)
Для изменения текущего масштаба карты вам доступны несколько жестов:
-   Щепок.
-   Двойное касание.
-   Касание двумя пальцами.
-   Двойное касание с прокруткой.
Для отключения всех жестов масштабирования используйте свойство isZoomGesturesEnabled.
```swift
mapView.isZoomGesturesEnabled = false
```
Далее рассмотрим каждый из жестов масштабирования.
### Щепок (pitch)
Изменяйте расстояние между двумя пальцами (сводите и разводите их) для изменения уровня увеличения.
### Двойное касание
Дважды коснитесь карты одним пальцем, чтобы приблизить камеру к месту касания.
### Касание двумя пальцами
Коснитесь карты двумя пальцами, чтобы отдалить камеру относительно центральной точки мест касания.
### Двойное касание с прокруткой
Дважды коснитесь карты одним пальцем и не отрывая палец проведите вверх или вниз по карте для изменения уровня масштабирования.
## Поворот
Совершайте вращательное движение двумя пальцами, чтобы повернуть камеру вокруг оси Z.
Для отключения жеста используйте свойство isRotateGesturesEnabled.
```swift
mapView.isRotateGesturesEnabled = false
```

===== userpointer | Индикатор пользователя
Размещайте на карте маркер пользователя для указания его текущего местоположения и направления.
## Overview
### Управление индикатором пользователя
Для управления индикатором пользователя необходимо использовать свойство userPointer из состава MapView. Для изменения положения маркера, размера круга точности и направления взгляда необходимо использовать один из доступных методов группы `setCurrentlocation`:
-   setCurrentLocation(coordinates:bearing:accuracy:animationDuration:)
-   setCurrentLocation(coordinates:accuracy:animationDuration:)
-   setCurrentLocation(bearing:animationDuration:)
В каждом из них вы можете указать длительность анимации перемещения маркера пользователя от предыдущей позиции к новой.
> NOTE:

### Получение текущей позиции индикатора
Для получения текущих значений индикатора пользователя используйте соответствующие методы контроллера UserPointerController:
-   coordinates - текущие координаты индикатора;

> NOTE:
>  Значения, получаемые с помощью перечисленных свойств, берутся не с GPS-контроллера устройства, а исходя из значений, которые вы отправили с помощью методов группы `setCurrentlocation`.

Для скрытия и показа индикатора служит свойство isVisible.
Так же индикатор пользователя не будет отображен, пока вы не отправите координаты с помощью одного из методов группы `setCurrentlocation`.

===== updatesdk | Переход с JS MapsSDK
Сделайте переход со старого JS MapsSDK на MapsNativeSDK максимально просто.
## Overview
MapsNativeSDK позволяет получить вам совершенно новый опыт работы с картографической информацией в ваших приложениях в сравнении с maps-sdk-ios. В этом руководстве будет описан процесс перехода с прошлой версии на новую.
## Установка MapsNativeSDK
MapsNativeSDK является не обновлением для JS MapsSDK, а полноценной новой библиотекой, поэтому вы не сможете совершить переход с помощью обновления пакета в SPM, пода в CocoaPods. Вам необходимо произвести установку MapsNativeSDK одним из способов, описанных в статье StartUsing.
## Переход на MapsNativeSDK
Для осуществления перехода на новую версию SDK сделайте следующий шаги:
### Шаг 1. Конфигурирование SDK
MapsNativeSDK требует произвести конфигурирование SDK до создания первого экземпляра `MapView`. Для конфигурирования служит метод `MapsSDKConfigurator/setup(baseURL:apiKey:diskCachePath:maxCacheSizeBytes:fileTimeoutSec:)`. Подробнее о его использовании можно прочитать в статье StartUsing.
```swift
// БЫЛО
// Предварительное конфигурирование SDK не требовалось

// СТАЛО
MapsSDKConfigurator.setup(apiKey: ##API-ключ##)
```
### Шаг 2. Конфигурирование MapView
Теперь конфигурацию карты (стартовое положение камеры, стартовый стиль), а так же делегат необходимо передавать в инициализатор объекта `MapView` (init(frame:configuration:delegate:)).
```swift
// БЫЛО
// Создаем объект карты
let mapView = MapView()
// Создаем объект конфигурации
let mapConfig = MapViewConfig(
    apiKey: "##API_KEY##",
    center: Coordinates(lng: 33, lat: 55),
    zoomLevel: 11,
    style: .automatic
)
// Устанавливаем конфигурацию
mapView.setup(mapConfig)
// Устанавливаем делегат
mapView.delegate = self

// СТАЛО
let configuration = MapConfiguration(
    center: Coordinates(
        lng: 35.910974,
        lat: 56.859207
    ),
    zoom: 15,
    predefinedStyle: style,
    selectFeatures: .all,
    cameraMode: .earth
)
// Передаем конфигурацию и позже отдельно устанавливаем делегат
mapView = MapView(configuration: configuration)
mapView.delegate = self

// ИЛИ
// Передаем конфигурацию и делегат одновременно
mapView = MapView(configuration: configuration, delegate: self)
```
### Шаг 3. Изменение методов перемещение камеры
Для перемещения камеры теперь необходимо обращаться к контроллеру CameraController через свойство camera. Ранее методы управления находились непосредственно в API класса `MapView`.
Для перемещения камеры используется методы группы `flyTo` и другие. Подробнее об это читайте в статье CameraMoving.
```swift
// БЫЛО
mapView.flyTo(Coordinates(lng: 33, lat: 55), animated: true, duration: 2)

// СТАЛО
mapView.camera.flyTo(coordinates: .center(Coordinates(lng: 37.427278, lat: 55.756486)), 
                        cameraOptions: .init(bearing: 80, zoom: 12, pitch: 0), 
                        animationOptions: .init(easing: .easeInOut, duration: .max(value: 2)))
```
### Шаг 4. Изменение методов управления индикатором пользователя
Для управления индикатором пользователя на карте необходимо обращаться к контроллеру UserPointerController через свойство userPointer. Ранее методы управления находились непосредственно в API класса `MapView`.
Для отображения и перемещения индикатора пользователя используется группа методов `setCurrentLocation`. Подробнее об это читайте в статье UserPointer.
```swift
// БЫЛО
mapView.setCurrentLocation(Coordinates(lng: 33, lat: 55), bearing: 0, accuracy: 0)

// СТАЛО
mapView.userPointer.setCurrentLocation(
    coordinates: Coordinates(lng: 33, lat: 55),
    bearing: 0,
    accuracy: 0,
    animationDuration: 1)
```

В MapsNativeSDK сильно переработана система событий, они стали более логичными. Теперь практически для всех типов событий (перемещение камеры, клики по маркерам, события жизненного цикла карты) используется метод mapView(_:didReceiveEvent:)-7k969.
