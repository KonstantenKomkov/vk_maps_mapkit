# Публикация пакетов

Порядок и проверки. Пакеты зависят друг от друга, поэтому публиковать их
можно только снизу вверх — иначе `pub` не разрешит зависимости.

## Порядок

1. `vk_maps_mapkit_platform_interface`
2. `vk_maps_api` (ни от чего не зависит, можно раньше)
3. `vk_maps_mapkit_android`
4. `vk_maps_mapkit_ios`
5. `vk_maps_mapkit_web`
6. `vk_maps_mapkit`

## Перед каждой публикацией

- [ ] `make check` зелёный;
- [ ] `CHANGELOG.md` пакета описывает изменения этой версии;
- [ ] версия в `pubspec.yaml` поднята, зависимости на соседние пакеты
      указывают на уже опубликованные версии;
- [ ] `dart pub publish --dry-run` без замечаний;
- [ ] в архиве нет секретов: `dart pub publish --dry-run` печатает список
      файлов, ключ доступа не должен попасть ни в один из них;
- [ ] `pubspec.yaml` содержит `repository`, `issue_tracker` и `topics`;
- [ ] версия нативного SDK одинакова в `Package.swift` и `.podspec`.

## Перед первым релизом 0.1.0

- [ ] чек-лист [живой проверки](live-verification-plan.md) заполнен по всем
      трём платформам;
- [ ] [матрица поддержки](platform-matrix.md) отражает фактическое поведение,
      а не намерения;
- [ ] в README перечислено, чего пакет не делает;
- [ ] получен ответ вендора по вопросам из
      [`questions-for-vendor.md`](questions-for-vendor.md), и решения
      обновлены, если ответ что-то меняет.

## Правило версий

Пакеты остаются ниже `1.0.0`, пока живая проверка не закрыта целиком.
Мажорную версию нельзя выпускать с непроверенной платформой: `1.0.0`
означает обещание совместимости, которое нечем подтвердить.

## Что проверить у web-пакета отдельно

- [ ] `flutter build web` в примере проходит;
- [ ] версия `MMR GL JS`, на которой шла проверка, записана в
      [`platform-matrix.md`](platform-matrix.md): по умолчанию плагин грузит
      последнюю `0.x.x`, и поведение может измениться без нашего участия.

## Файлы, которые не публикуются

`pubspec_overrides.yaml` в архив не попадает — это локальная связка пакетов
на время разработки. Перед публикацией стоит убедиться, что пакет собирается
и без него.
