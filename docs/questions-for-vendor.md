## Текст письма

**Тема:** VK Карты: доступ к Android-артефактам нативного SDK и вопросы по возможностям

Здравствуйте!

Мы разрабатываем открытый Flutter-плагин — обёртку над нативными SDK VK Карт для Android и iOS, с публикацией на
pub.dev. Плагин делается сторонней командой, подключает ваши SDK зависимостью — бинарники мы не вендорим и не
перевыкладываем; ключ доступа каждый пользователь плагина получает самостоятельно.

По iOS всё необходимое доступно: SDK ставится через CocoaPods (`VKMapsSDK`) и SPM
(`maps-mailru/vk-maps-distribution`, релиз 1.4.4.14633 от 26 августа 2026), API восстанавливается по DocC-архиву
из дистрибутива. Ниже три вопроса: первые два — по Android, третий — по возможностям SDK на обеих платформах.

**1. Где сейчас лежат Android-артефакты нативного SDK?**

Страница документации `https://dev.vk.ru/ru/vkmaps/maps-mobile-sdk/android` предлагает подключить репозиторий
`https://artifactory-external.vkpartner.ru/artifactory/maps-sdk-android/` и зависимость `ru.mail.maps:mapkit`.
На 8 сентября 2026 обе ссылки со страницы отдают 404:

- `https://artifactory-external.vkpartner.ru/artifactory/maps-sdk-android/` → 404
- `https://artifactory-external.vkpartner.ru/artifactory/maps-sdk-android/ru/mail/maps/mapkit/` → 404
  (ссылка «Последнюю версию SDK можно найти по адресу» на той же странице)

Судя по всему, выкладка переехала: корень `artifactory-external.vkpartner.ru/artifactory/` редиректит на
`https://nexus-external.vkteam.ru/`, и страницу 404 отдаёт уже Sonatype Nexus. В публичном списке репозиториев
Nexus (`/service/rest/v1/repositories`) карт нет, поиск по группе `com.vk.maps` и по `maps-native-sdk` пустой.
Зеркала на Maven Central тоже нет.

Подскажите, пожалуйста:
- актуальный адрес и имя репозитория, откуда сейчас забирать Android-артефакты;
- нужны ли для доступа учётные данные, и если да — как их получить;
- актуальные координаты зависимости (`ru.mail.maps:mapkit` или `com.vk.maps:maps-native-sdk`) и список версий.

**2. Есть ли документация нативного Android SDK?**

На сайте описан SDK поколения `ru.mail.maps:mapkit` (`MapGlobalConfig`, `MapStartOptions`, `MapView`, `ZoomView`,
`CurrentLocationView`, `CompassView`). При этом на iOS актуальным является нативное поколение
(`MapsNativeSDK`/`VKMapsSDK`, рендер Metal/Vulkan), которое на сайте не описано.

Подскажите:
- какое поколение SDK вы считаете актуальным для новых Android-интеграций;
- есть ли документация нативного Android SDK (аналог DocC-архива, который поставляется для iOS) и где её взять.

**3. Кластеризация и источник для ломаных в нативном SDK**

В DocC-символах нативного iOS SDK мы не нашли ни одного типа, связанного с кластеризацией, тогда как в
документации legacy-поколения кластеры есть (`addCluster`/`removeCluster`). Верно ли, что в нативном SDK
кластеризации сейчас нет и планируется ли она? Тот же вопрос про источник для ломаных (polyline) — доступен ли он
как отдельный источник или ожидается работа через стилевые слои и GeoJSON.

От ответа зависит, реализуем ли мы кластеризацию на стороне Flutter.

Заранее благодарим за ответы: первые два вопроса определяют сроки по Android-части, третий — объём работ на
стороне Flutter.
