# vk_maps_mapkit_android

Android-реализация плагина `vk_maps_mapkit`.

Подключать напрямую не нужно: пакет попадает в приложение вместе с фасадом
[`vk_maps_mapkit`](../vk_maps_mapkit).

## Состояние

**Пакет не собирается.** Артефакт SDK недоступен: адреса из документации
отдают 404, выкладка VK переехала на Nexus, актуальные координаты запрошены
у вендора — см. [`questions-for-vendor.md`](../../docs/questions-for-vendor.md).

Из этого следует, что **имена пакетов и сигнатуры в Kotlin-коде не
проверены компилятором**. Они взяты со страницы документации
`dev.vk.ru/ru/vkmaps/maps-mobile-sdk/android`, где показаны только имена
классов (`MapGlobalConfig`, `MapView`, `Map`, `MarkerEntity`, `MapLocation`,
`GeojsonSource`, `PolylineSource`), но не пакеты, в которых они лежат.
Импорты `ru.mail.maps.sdk.*` и `ru.mail.maps.data.*` — предположение, и
первое, что придётся уточнить, когда артефакт появится.

Опыт с iOS показывает, что так и будет: там сборка вскрыла семь расхождений
между документацией и модулем (см. [решение Р-9](../../docs/design-decisions.md)).

## Что уже учтено

- сборка на Kotlin DSL, `minSdk 24`, JDK 17, lint как ошибки;
- вызовы SDK идут в главном потоке, как требует документация;
- команды, пришедшие до готовности карты, складываются в очередь:
  `getMapAsync` асинхронный, иначе первые команды из Dart терялись бы;
- возможности, которых нет в документированном SDK, отвечают ошибкой
  `unsupported` — их список в [матрице поддержки](../../docs/platform-matrix.md).
